# Drawer tab bar — emulation sign-off

**Date:** 2026-08-03
**Environment:** Obsidian desktop in mobile emulation (`obsidian dev:mobile on`), window resized to 402×874, `Platform.isPhone === true`, `window.innerWidth === 402`
**Branch:** `feat/drawer-tab-bar` @ `a8b7c95`
**Verified by:** controller session, not a subagent — the checks drive Obsidian directly and have to restore the environment afterwards.

Real device sign-off on an iPhone is still outstanding. Emulation runs the same
renderer and the same `is-phone` code paths, but it is not the same WebKit, and
the predecessor of this feature shipped three positioning defects that only a
real screen exposed. Treat this as "the mechanism works", not "it feels right".

## Results

### Bar mounts in the RIGHT drawer

```json
{"right": true, "rightPills": 5}
```

### Bar mounts in the LEFT drawer

This is the one the previous version never had — it handled the right drawer
only.

```json
{"left": true, "leftPills": 6,
 "labels": ["Files", "Search", "Tags", "All properties", "bookmarks", "Portal"]}
```

The labels are read live from the drawer's real tabs, which is why they are the
actual view names rather than anything configured.

### Tap switches the tab

Tapping the third pill in the left drawer:

```json
{"before": {"idx": 1, "type": "search"},
 "after":  {"idx": 2, "type": "tag"}}
```

### Swipe switches the tab

A synthetic leftward drag of 220px over
`.workspace-drawer.mod-left .workspace-drawer-active-tab-container`
(touchstart → 15 touchmoves → touchend, dispatched on the host element in a
single evaluation so the listeners see one coherent gesture):

```json
{"currentTab": 3, "type": "all-properties"}
```

Before the gesture the drawer was on tab 2 (`tag`), so the swipe advanced
exactly one section — `decideSnap` → `selectDrawerTab` → Obsidian's own
`selectTabIndex`.

### Geometry

```json
{"drawerRect": {"x": 0, "w": 402, "h": 874},
 "drawerTransform": "none",
 "barRect": {"x": 12, "w": 378},
 "collapsed": false}
```

The bar spans the drawer's width inside its margins, with no transform applied
to the drawer itself.

### Screenshot

`/tmp/drawer-final.png` — the left drawer open, six pills across the top with

replacement.

## Not covered here

- **Real iPhone.** Emulation cannot reproduce iOS WebKit's touch behaviour, and
  in particular cannot confirm the tap-vs-swipe discrimination on a real thumb
  — the defect the Task 3 review caught (a wobbly tap being swallowed by
  `preventDefault`) is exactly the class of thing that needs a real finger.
- **The accepted Bases regression.** With the swipe claiming every horizontal
  drag in a drawer, Bases tables can no longer be scrolled sideways while the
  toggle is on. Chosen knowingly; not re-litigated here.
- **Reduced motion.** The pills' `prefers-reduced-motion` rules survived the hub
  deletion (verified in the Task 1 review) but were not exercised on screen.

## Environment restored

`drawerTabs` set back to `false`, both drawers collapsed, `dev:mobile off`,
window back to 1512×949 full-screen, `Platform.isPhone === false`. Leaving
Obsidian in emulation breaks Exo, which needs desktop Node access.
